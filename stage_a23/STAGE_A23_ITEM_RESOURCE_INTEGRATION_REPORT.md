## 7. 人工验收

1. 运行 `RunStageA23.bat`，从 501 开门出门，确认未授权楼层没有提前暴露物资模型。
2. 在五楼原箱顶观察水瓶；分别按 F5/F2/F1，确认尺寸、方向、光照和遮挡可接受。
3. E 领取后水瓶陈列消失、箱体变为空态；I 打开背包，水×2、绷带×2。重复 E 不增加数量，关闭背包后控制正常。
4. 沿原楼梯到四楼，在原箱顶观察罐头与电池；三角度下确认没有缺面、材质错误或穿箱。E 后获得电池×3、罐头×2。
5. 到三楼领取原两种武器，检查背包六种数据仍正确；返回四楼，模型不应恢复。
6. 连续探索至少两分钟，留意转角、相机遮挡、模型闪烁、空箱状态及偶发卡顿。自动截图不能代替操作手感与长时间稳定性验收。

正式入口不提供刷满背包功能；满包安全性已由自动用例验证，不为人工验收增加新的玩法功能。

## 8. 已知限制与后续建议

- 三件小物品在正常视野中仍只有少量像素；能识别色块与轮廓，但标签与电极符号主要在近景可读。剩余美术细节按玩家要求冻结，未放大或重新造型。
- 陈列样品不等于真实散落的所有数量，也不能单件点击领取；底层仍是原配置容器全量原子领取。
- 没有通用地面掉落、武器手持、物资使用或存档接入；本轮不添加这些系统。
- 原 HUD 的文字局部重叠仍可见，本轮没有改 UI。四楼的既有栏杆和剖切表现也保持原规则。
- 当前小件箱顶布局适配原容器，未来长武器或不同柜体应单独提供陈列面布局，不能假定任何模型都适合当前小箱。
- 背包当前文字 UI 已满足数据查看。后续若授权图标阶段，优先使用已验收模型统一离线预渲染，再复用现有 icon 字段与事件刷新；不建议每个槽位运行实时 3D。统一占位图标可作过渡，但不能准确区分物品。本轮只评估，不生成图标或修改背包。
